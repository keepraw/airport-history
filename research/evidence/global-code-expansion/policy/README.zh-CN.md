# 全球历史代码来源家族准入提案

本提案以 main `7d21ff6762e1569faa1be19c8203e577420cd1f2`、正式数据 0.11.0 为基线，状态为 **proposal-only**。`proposal.json` 集中列出 48 个国家／发行机构来源家族及其适用证据、版权与时间边界要求；它不激活代码准入，也不修改现有授权、正式数据或 Executor。来源入口待核验的家族与已经取得原件的家族分别记录；列入提案不等于已经取得其历史 AIP。

## 对两类代码分别要求什么

IATA 可以采用合法取得的 IATA 历史分配／迁转／撤销通知，或主管机关、机场运营商明确说明**该代码**对**该物理机场**的生效通知。当前代码检索、航空公司航点目录、机场开航、批准或网页抓取日期均不能代替代码生效日。运营商通知是否足以入库，应由同一次来源家族规则授权明确接受，且需处理其分配信息来源与反证。

ICAO 可以采用受控 AIP AD 2、修订／AIRAC、正式地点指示码通知及完整 NOTAM 生命周期。必须分别记录公布日、版本生效日、组件修订日及代码有效日，核实物理场址。完整有效版本链可以支持经过明确授权的有界连续性判断；**本提案没有新增一个全球通用的观察间距阈值**。缺少中间版本的两个观察点继续保留为两个观察，不能补成连续区间。

每份资料记录原始、提取及规范化文本 SHA-256，出版者／版本、引用位置、日期性质和事实来源。相同原件的不同 URL、镜像、下载和 Git 修订不增加来源独立性；同发行机构多个版本可以支持时间核验，但不是多个独立发行机构。坐标纠正、目录纠错、航站楼更换、民航停运与物理关闭分别分类。代码相同或城市相同不合并物理身份。

## 权利与准入是三个独立条件

1. **可取得**：合法公开访问或已有许可；403、登录限制等按实际结果记录，不绕过。
2. **可使用**：每份原件的事实／必要短引文与数据库衍生使用依据明确；公开网页不是开放许可，Owner 也不能授予第三方版权。
3. **可准入**：适用项目来源家族授权、足够代码／物理场址／有效期证据、无未处理实质冲突及现有准入验证全部通过。

完整原件与完整提取文本只留在 ignored `work/`。政府文件也按发行机关、文件类型和第三方内容逐件限定；中国行政文件、美国联邦官方作品、县属机场网页、NAV CANADA、DFS、ENAIRE、DECEA 等不能互相继承版权结论。未知依据继续列为研究候选，不在正式来源注册表写入未经证明的许可。

## AAI 固定数据入口的已验证复用

现有 AAI 授权允许未来同范围低风险记录，但当前已实现的数据入口仍固定在旧研究产品：

- `scripts/evidence/policy_review.py:25` 固定 `STAGES = global/markets/transfers/direct`；`inputs()`（约 85–140 行）只从这些阶段的既有 proposed-data、dossier、source-lock 取得记录，不读取本轮目录。
- `scripts/evidence/policy_gate.py:130` 附近的 `packet()` 从 `global-evidence-proposal-1/2.json` 获取事件模板；新记录必须有真实、唯一的模板及引用，不能冒用旧事件。
- `scripts/evidence/policy_review.py:389` 的 `freeze_inputs()` 可从真实发布的当前基线锁定一组新**数据输入**，但不会自行创建新记录或事件模板。
- `scripts/evidence/legacy_replay.py:31–37` 对 `1e35d42` 的所有原有脚本、测试、研究文件逐字节比较。直接追加旧阶段输出或刷新旧 `research/policy/input-lock.json` 会使当前归档重放失败。既有 PR22 归档也不能免除这项检查。

本轮已在新目录提供 VOSH／VEAY／VANM 的数据入口包：稳定的合法物理 UUID、原件锁、最小引用、参考物理身份、独立真实事件模板及冲突筛选。准备时在 ignored `work/` 的隔离 checkout 中保持 AAI grant 绑定的可执行文件逐字节不变，以真实已发布 0.11.0 为旧基线，将数据追加到该隔离副本原有输入结构，运行原有 `freeze`、`build`、`admit`。该执行器实际重放了六份 AD 2 和一份版本控制原件，成功生成三条已验证 ICAO 记录的 0.12.0 提案。新锁绑定本轮实际读入的数据，没有改写旧锁或伪造旧输入。

正式重放组装限制已经解决：[`replay-manifest.json`](aai-intake/replay-manifest.json) 记录十三个仅含研究数据与最小引用的输入快照。`scripts/evidence/global_code_admission.py` 在临时发布基线 checkout 恢复这些数据，调用同一个未修改的 `policy_formal.py` 原准入 CLI，并验证授权执行器指纹及原件核验收据；此处是明确的离线收据重放，不宣称重新取得私有原件。历史中国 0.11.0 身份准入先在其原始字节上重放。现有政策、授权、阈值、执行器、旧研究输入和旧归档检查保持不变，组装辅助脚本不提供新审批或新证据规则，也没有新增国家 Executor。

[`0.12.0 准入记录`](../../../admissions/0.12.0/README.md) 保存正式数据提案与原有 gate 生成的完整收据。最终合并仍由人工决定；该已通过准入和生产解析器验证的提案不能预先计入 main 的实际覆盖。本次成功也不会扩大 AAI 授权到 IATA、竞争场址、其他来源家族或其他国家。

## 一次性集中决策范围

提案请求对已充分核实的来源家族和证据类别作项目级决定：允许符合规则的多个国家、多个机场集中形成数据 PR；具体原件仍须满足事实、时间、使用权和冲突条件。IATA 与 ICAO 分别授权，明确何种运营商直接通知可接受；任何新 AIP 有界连续性规则必须写清版本完整性要求。无需逐机场批准，也没有新的审批服务、下载服务、独立发布系统或国家 Executor。`proposal.json:ownerAuthorizationRequested` 给出具体请求，但目前 authorization 为 null，productionEnabled 为 false。最终合并保留人工决定，不自动合并或创建 Release。

本轮另取得 Manas FRU→BSZ 与 TAROM KIV→RMO 的 IATA 变更日材料，新增两个明确的运营商／承运人来源家族档案。Manas 的 IATA 通知为第三方镜像，发行者真实性、通知生命周期与实际执行仍待核实；TAROM 是承运人预告。它们均只保留代码边界事实和具体待核事项，不新增连续 IATA 有效期，也不激活来源家族授权。
